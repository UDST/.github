# Credit and attribution

UDST records both the continuity of project leadership and the contributions of the wider community.

## Founding and stewardship

UrbanSim was created by Paul Waddell. He has led its development across more than three decades as principal investigator, co-principal investigator, research lead, software architect, founder of UrbanSim Inc., and owner and steward of the UDST GitHub organization.

This continuity should be stated in the organization history and in descriptions of the research program. It does not replace credit for the investigators, developers, students, agencies, and independent contributors whose work built the projects.

## Repository-level credit

Each active repository should maintain an accurate account of its origins and principal contributors. The account should be based on public evidence, including:

- repository and predecessor history;
- release notes and package metadata;
- published papers and technical reports;
- preserved commit authorship and pull-request history; and
- project documentation from the period in which the work was done.

Commit counts alone are not a reliable measure of intellectual or technical contribution. Large migrations, institutional account changes, squashed commits, and work completed before GitHub can obscure authorship.

## Contributions from forks and funded projects

When work is recovered from a fork, the source repository, commits, and original authors should be identified. Authorship should be preserved where practical. If code must be rewritten, release notes or pull-request text should still provide appropriate credit.

Funded work should identify the sponsor when attribution is permitted, but funding does not make the sponsor the author or owner of the repository. Contractors and agency staff receive credit for their actual contributions under the same standards as other contributors.

## Publications and software citation

Repositories should provide a `CITATION.cff` file or equivalent citation guidance where a stable software citation exists. Users should cite both the relevant software release and the research publication that describes the method, when applicable.

## Proposed repository audit

Before publishing an organization-wide list of named contributors, UDST should complete a repository-by-repository audit. The audit should establish:

1. the origin and predecessor history of each project;
2. founding authors and principal maintainers;
3. contributors obscured by repository migrations or squashed history;
4. the correct institutional affiliations for the period of contribution; and
5. an appropriate software citation.

Until that audit is complete, the Git history and repository acknowledgments remain the authoritative contributor record. No draft list should be presented as exhaustive.
