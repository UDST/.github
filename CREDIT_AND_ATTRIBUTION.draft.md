# Credit and attribution

UDST records the continuity of project leadership and the work of its
contributors.

## Founding and stewardship

UrbanSim was created by Paul Waddell. He has provided continuous leadership
for more than three decades as principal investigator, co-principal
investigator, research lead, software architect, founder of UrbanSim Inc., and
owner and steward of the UDST GitHub organization.

The organization history and descriptions of the research program should state
this continuity. They should also credit the investigators, developers,
students, agencies, and independent contributors who built the projects.

Credit should identify the nature of a contribution where that distinction is
useful. Scientific conception and leadership, securing research funding,
project direction, software design, code authorship, maintenance,
documentation, and institutional support are different contributions.
Recognition of one does not displace the others.

## Repository-level credit

Each active repository should maintain an accurate account of its origins and
principal contributors. The account should be based on public evidence,
including:

- repository and predecessor history;
- release notes and package metadata;
- published papers and technical reports;
- public award and institutional records;
- preserved commit authorship and pull-request history; and
- project documentation from the period in which the work was done.

Commit counts alone are not a reliable measure of intellectual or technical
contribution. Large migrations, institutional account changes, squashed
commits, and work completed before GitHub can obscure authorship.

## Contributions from forks and funded projects

When work is recovered from a fork, the source repository, commits, and
original authors should be identified. Commit authorship should be preserved
where practical, and applicable license and copyright notices must be retained.
If code must be rewritten, release notes or pull-request text should still
provide appropriate credit.

Funded work should identify the sponsor when attribution is permitted, but
funding alone does not confer authorship, copyright, or administrative control
of a repository. Contractors and agency staff receive credit for their actual
contributions under the same standards as other contributors.

## Publications and software citation

Repositories should provide a `CITATION.cff` file or equivalent citation
guidance. Users should cite the relevant software release and, when applicable,
the research publication that describes the method.

## Repository credit review

Before publishing an organization-wide list of named contributors, UDST should
review each repository's available records. The review should establish:

1. the origin and predecessor history of each project;
2. founding authors and principal maintainers;
3. contributors obscured by repository migrations or squashed history;
4. relevant, publicly documented institutional affiliations at the time of the
   contribution; and
5. an appropriate software citation.

Repository histories, acknowledgments, publications, release records, and
project documentation together provide the best available record. No
organization-wide list should be presented as exhaustive.
